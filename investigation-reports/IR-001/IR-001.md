# IR-001: Post-Compromise Tool Transfer and Persistence (Chained Simulation)

**Classification:** Controlled Simulation
**Analyst:** Boluwaji Oluwaseyi Adepoju
**Date:** 29/03/2026
**Status:** Closed
**Severity:** High
**Host:** DESKTOP-MM1REM9 (10.0.20.10), Windows 10 Pro 22H2
**MITRE ATT&CK:** T1105, T1053.005, T1059.001 (attempted), T1218.003

---

## 1. Summary

On 29/03/2026 I saw post-compromise activity on the Windows 10 endpoint
DESKTOP-MM1REM9. An attacker used certutil.exe, a legitimate Windows tool,
to download a file from the internal attack host (10.0.30.10). Right after,
they created a scheduled task that runs an encoded PowerShell command as
SYSTEM at logon.

This was a chained workflow: tool transfer followed by persistence. It
simulates how an operator behaves after initial access is already in hand.

Windows Defender blocked the first download attempt, so the preventive
controls were working. The control was then bypassed and persistence went
through.

**Current status:** Activity contained in the lab. No lateral movement, no
data exfiltration. Artifacts left on disk for analysis.

**Worst case if real:** The scheduled task gives the attacker SYSTEM-level
execution on every logon. That is long-term access that survives reboot.
This pattern shows up in the dwell phase before ransomware.

---

## 2. Technical Detail

### Methodology

**Collection:** Sysmon (Event IDs 1, 3, 11) via Elastic Agent. I analyzed
the logs in Kibana Discover with field queries against `winlog.event_data.*`.
No dashboards.

**Analysis:** I correlated events by `agent.name: "DESKTOP-MM1REM9"` and
found four key events inside a 52-second window, linked by process behavior
and timing.

**Enrichment:**

* certutil.exe: T1105, T1218.003
* schtasks.exe: T1053.005
* Encoded PowerShell: T1059.001 (execution not observed)

**Conclusion:** The endpoint downloaded a file from an attacker-controlled
host and set up persistence through a scheduled task that runs an encoded
PowerShell command. Classic post-compromise staging.

### Baseline and Tripwires

**Network baseline:** Suricata on OPT1 sees traffic between the two
networks, but its detection was limited to SYN scans (SID 9000001). The
HTTP download passed through Suricata with no alert because no rule
matched it.

**Endpoint baseline:** Sysmon with the SwiftOnSecurity configuration is
active. The scheduled task creation got tagged automatically with
`RuleName: T1053`, so the endpoint side did its job.

**Investigation type:** Reactive triage on observed activity.

### Breach Chain

**Initial access:** Out of scope. Assumed via an existing user session.

**First observed activity:** 2026-03-29T16:09:57.441Z

**Tool transfer:** certutil.exe opened connections to 10.0.30.10:80 and
downloaded a file to disk.

**Persistence:** schtasks.exe created a scheduled task named
"SystemHealthCheck" that runs encoded PowerShell as SYSTEM at logon.

**Privilege context:** Elevated integrity. Task configured to run as SYSTEM.

**Data exfiltration:** None observed.

**System impact:** A file on disk and a scheduled task. Persistence
established.

**Threat context:** The behavior matches living-off-the-land TTPs used by
multiple threat groups. This is pattern matching, not attribution.

### Notable Observations

* certutil.exe made two TCP connections milliseconds apart. That is its
  known dual-request behavior.
* The scheduled task holds an encoded PowerShell command. The attacker
  wanted the execution obfuscated.
* schtasks.exe itself is legitimate. The arguments are what make it
  malicious.
* The 52-second gap between stages looks like operator interaction time.

## 3. Gaps and Remediation

### Detection Gaps

**Gap 1: No alert for HTTP tool transfer**

Traffic crossed Suricata but matched no rule.

**Fix:**

```
alert http 10.0.20.0/24 any -> 10.0.30.0/24 80 (msg:"LOCAL HTTP outbound victim to attack network"; sid:9000002; rev:1;)
```

**Gap 2: Defender disablement not detected**

Defender blocked execution and was then bypassed, with no alert.

**Fix:** Monitor Defender tampering:

```
agent.name: "DESKTOP-MM1REM9" AND event.code: "13" AND winlog.event_data.TargetObject: *Windows Defender*
```

**Gap 3: Missing certutil process creation event**

Event ID 1 was not captured for certutil. Execution was confirmed only
through Event ID 3.

**Fix:** Review the Sysmon config for ProcessCreate coverage.

### Remediation

* Re-enable Defender real-time protection
* Remove the scheduled task
* Delete the dropped file
* Revert the VM snapshot if required

### Mitigation

* Restrict LOLBin network usage with ASR rules
* Limit scheduled task creation through policy
* Enforce outbound traffic controls
* Alert on encoded PowerShell usage
* Monitor Defender disable events in real time
